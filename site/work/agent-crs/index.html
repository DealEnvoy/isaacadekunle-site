Case study

Agent CRS

Testnet

A release check for agent spending. The vault holds the NEAR. The agent can ask for a spend. It cannot pay itself, and it cannot approve.

Repository Vault on NEAR testnet 68 second demo video CRS Pilot 0

Problem

An agent that can sign with a full access key can move every token on the account. Passing the agent's tests does not change that. Agent CRS puts the money in a contract and gives the agent a key that cannot transfer NEAR and cannot call the approval methods.

Architecture

ShippedA release check for agent spending on NEAR testnet. The vault holds the NEAR. The agent holds only a function call key that can ask for a spend. The contract pays only when the receiver is allowlisted and the amount fits the per transaction cap and the daily cap. Anything else waits for the owner, or is denied.

The owner sets policy and approves or rejects with a full access key, attaching 1 yoctoNEAR. The agent calls request_spend with no deposit. The contract releases a payment that fits the allowlist and the caps, queues one that needs the owner, or denies one it will not pay. Every proposal, queue, approval, rejection and execution is stored on the contract. A small board reads that state. The board is not hosted.

LimitThe board is not hosted. The repository starts it locally with npm run dev from the web directory. The public evidence is the NEAR testnet vault and a 68 second demo video in docs/demo.

The repository says the deployed policy at the time of writing was 0.5 NEAR per transaction and 10 NEAR per day, with the vendor account allowlisted. Contract tests use their own caps and do not depend on that deployment.

Stack

  • Contract: Rust, near-sdk 5.30.1. The build noted in the README used Rust 1.99.1.
  • Agent and board calls: Node.js 22 or newer, near-api-js 5.1.0.
  • Board: Next.js, not hosted. From the web directory the README uses npm run dev, then opens 127.0.0.1:43123. It can read the public vault with no keys.
  • RPC: test.rpc.fastnear.com, with rpc.testnet.near.org as fallback.

The scripts refuse any network id other than testnet. Proposing and approving from the board need credential files that are not in the repository.

What Isaac owned

ShippedBuilt by Isaac Adekunle / Drew & Crew with AI coding agents, for NEAR Hackathon 2026.

He directed the project. AI coding agents assisted the implementation. The repository says the third-party pieces are near-sdk, near-cli-rs, near-api-js, Next.js, and a shadcn/ui button primitive. No earlier product code is included.

Agent CRS is separate from Approve before Pay, the PayPal hackathon entry. They do not share a repository, a contract, or a product.

It is from crs-ai-agents, CRS Pilot 0: an advisory check of whether a model notices when a finished work pack does not support its own "done" statements. False alarms are a separate column in that repository.

ShippedThis figure is from crs-ai-agents, CRS Pilot 0, an advisory evaluation. It is not a result for the Agent CRS vault, and it is not a result for airworthiness-mcp. Each of three models caught the seeded fault in 16 of 16 tries (8 faulty packs, run twice).

Limitcrs-ai-agents reports false alarms on the clean twins as a separate measure, not as part of the 16 of 16 detection line. The repository summarises those false alarms as 19% to 50%. Each reported 16 is eight faulty packs with two epochs, recorded on a first run and on a second run. With 16 trials the Wilson lower bound is 0.81, so the detection line means no misses were seen on those packs. The second run repaired some clean twins after the first results were seen. The pilot is small and self-registered. It is not a certification tool.

Scoring was by code: detection, location, an exact quote, false alarms, invented quotes, and forbidden release language. The repository also records a $100 spend cap in the pilot's own cost guard, and a logged spend of $11.79 against that cap. Cost figures there are list-price estimates, not invoices.

Tests and the demo

ShippedThe repository documents 26 contract tests and 4 parser tests. The recorded demo states that no model was called.

The contract tests cover default deny, the allowlist, both caps, pause, a failed transfer callback, and the 1 yoctoNEAR check on owner methods. The parser tests run with no API key. The 68 second Playwright recording in the repository types two sentences, shows an in-policy release, shows an over-cap queue, approves it with the owner key, and shows the audit log. The caption says no model was called.

Limits

LimitTestnet only. The repository says this is not custody advice and it does not hold mainnet funds. The name is an analogy for a human release check, not a certification, and it is not affiliated with any aviation authority.

The repository also says the vault account still has an operator full access key, held outside the repository, so that upgrades are still possible. That key can transfer NEAR without the policy. The agent account cannot. The policy is an allowlist plus two caps. It is not a compliance engine.
